# worldscan-v2-video-product

Restructure WorldScan from a single-photo HTML prototype into a clean,
multi-stage video product with a typed React frontend, a FastAPI backend, a
durable job system, a physics-validation gate, and persistent project history.
The existing Python RL pipeline (`rl_env/`) is preserved as a library and
consumed by the new backend; nothing about its behaviour changes.

## Why

The current product has three structural problems we cannot fix incrementally:

1. **Single-photo reconstruction caps quality.** A chair photographed from one
   angle yields a 2.5D shell, open at the back; the agent walks past the
   captured surface (`prototype/v1.html` warning, confirmed in
   `rl_env/README.md:121-122`). No amount of policy tuning fixes this — the
   geometry is wrong.
2. **No validation gate.** A bad reconstruction (2 hulls instead of 7+, scale
   off by 10×, no floor detected) silently builds a broken MJCF and trains a
   broken policy. Users currently cannot tell whether reconstruction failed or
   the agent failed.
3. **The UI is a 2000-line HTML monolith.** `prototype/v3.html` mixes
   reconstruction, build, train, replay, and benchmark into one global-scope
   `<script>`. Adding a sidebar, project history, or a second task type means
   either a fourth `vN.html` or a real rewrite. We are choosing the rewrite.

A fourth, softer problem: the team maintains a sibling product (`Haleum/`)
that has already converged on a clean web stack. Adopting the same stack
above the ML/sim line means engineers move between the two codebases
without retraining muscle memory.

## What changes

### New product surface

A four-step linear flow per project: **Capture → Reconstruct → Validate →
Train & Replay**. Each step writes a durable artifact a user can return to.

- **Capture** — upload an `.mp4`/`.mov` (still images accepted for back-compat).
  Server samples frames with `ffmpeg`.
- **Reconstruct** — pluggable backend. v1 ships **VGGT** (feed-forward neural,
  GPU, ~seconds per scene). The interface is designed so Gaussian Splatting,
  classical COLMAP+MVS, and frame-sampled monocular depth can drop in as
  later changes without touching routes or UI.
- **Validate** — automated mesh sanity report: watertightness, connectivity,
  scale plausibility, floor detection, convex-decomposition quality. Each
  check is pass/warn/fail with a human-readable explanation and a recommended
  fix. The "Build env" button is gated on no `fail` results unless the user
  ticks an override checkbox.
- **Train & Replay** — same PPO as today, but with: live training metrics,
  trajectory overlay on the floor view, per-episode failure classification
  (`timeout`/`stuck`/`collided`/`near-miss`), side-by-side random/greedy/PPO.

A persistent **left sidebar** lists past projects (each project = one
captured video plus its downstream artifacts). Clicking a project loads its
full state from Postgres.

### New stack (aligned with `Haleum/` where possible)

| Layer | Choice |
|---|---|
| Frontend | React 19 + Vite + TypeScript + TanStack Router + TanStack Query + TanStack Form + Radix UI + shadcn pattern (`components.json`) + Tailwind v4 (`@tailwindcss/vite`) + Sentry + Posthog |
| Backend API | FastAPI (Pydantic v2, automatic OpenAPI) |
| DB / ORM | Postgres + SQLAlchemy 2.0 + Alembic migrations |
| Jobs | Inngest (Python SDK) + separate `worker.py` process; Inngest Dev Server locally, Inngest Cloud-ready for hosting |
| Shared types | OpenAPI 3 generated by FastAPI → `openapi-typescript` codegen → consumed by frontend |
| Repo shape | yarn workspaces monorepo (`frontend/`, `backend/`, `shared/`); root `docker-compose.yaml` runs api + worker + postgres + inngest-dev + frontend |
| Lint / format | ESLint + Prettier + Husky on TS side, Ruff + Black on Python side |
| ML / sim | `rl_env/` Python package, unchanged. Called by backend in-process; no IPC hop |

### What stays the same

- `rl_env/build.py`, `rl_env/env.py`, `rl_env/train.py` are untouched as a
  Python library. The new FastAPI routes call into them; the procedural
  sample room and `python -m rl_env demo` CLI keep working as a headless
  smoke test.

## Why now

We have a working RL pipeline (27/30 PPO success on the procedural room) and a
known-bad single-photo result on the chair scene (1/30, 2 hulls, 6 m vertical
extent). The bottleneck is **input quality**, and the path to fixing it means
swapping reconstruction techniques — which is exactly what the new pluggable
interface enables. Restructuring now, before we have multiple reconstruction
backends sharing one monolith, costs the least.

## Impact

- **Affected specs (new):** `video-reconstruction`, `physics-validation`,
  `project-history`.
- **Affected specs (modified):** `nav-env`, `rl-training`.
- **Affected code:** new `frontend/`, new `backend/`, new `shared/`,
  `prototype/` → `archive/legacy/`, `rl_env/server.py` deleted (replaced by
  `backend/src/features/*`), root `docker-compose.yaml`, root
  `pyproject.toml`, root `package.json` (yarn workspaces).
- **Breaking:** the URL `http://127.0.0.1:5174/prototype/v3.html` stops
  working; users open `http://127.0.0.1:5173/` (Vite). Existing
  `server_builds/` is migrated to `data/projects/<id>/build/` on first run.

## Out of scope (future changes)

- **Object segmentation (Tier 2).** SAM 2 + CLIP per-region material/object
  classification, per-object hulls. Separate change:
  `worldscan-v3-object-segmentation`.
- **Alternative reconstruction backends.** Designed for, not implemented.
  Future: `worldscan-v2.1-splat`, `worldscan-v2.2-colmap`,
  `worldscan-v2.3-depth-fusion`.
- **Cloud reconstruction.** Pluggable *execution location* — same backends,
  but offloaded to a remote GPU (Modal / Runpod / AWS) for splat-class work
  that doesn't fit on a laptop. Orthogonal to which backend is selected.
  Separate change: `worldscan-v2.4-cloud-reconstruction`.
- **Live / streaming / dynamic reconstruction.** Real-time ingestion from a
  WebRTC or HLS stream, incremental per-frame reconstruction, handling of
  moving objects (ego-motion vs object-motion separation). A different
  *input modality* than the batch video upload this change adds. Separate
  change: `worldscan-v2.5-stream-reconstruction`.
- **Vision-conditioned policies.** Out of scope this academic year.
- **Auth / multi-user.** Single-user local app. Hosting is a later
  conversation; Inngest Cloud and a managed Postgres make it cheap when we
  get there.
