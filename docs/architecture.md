# WorldScan architecture

Distilled from `openspec/changes/worldscan-v2-video-product/design.md`.

## High-level

```
┌──────────────────────────────────────────────────────────────────┐
│ frontend/  React 19 + Vite + TS                                  │
│   TanStack Router · TanStack Query · TanStack Form               │
│   Radix UI primitives + shadcn pattern · Tailwind v4             │
│   Geist Sans / Mono · Sentry / Posthog (no-op without DSN)       │
└────────────────────────────┬─────────────────────────────────────┘
                             │ HTTP (typed via OpenAPI codegen)
┌────────────────────────────┴─────────────────────────────────────┐
│ backend/  FastAPI + Pydantic v2                                  │
│   SQLAlchemy 2.0 + Alembic         → Postgres (5433 in dev)      │
│   Inngest Python SDK (functions)   → Inngest Dev (8289 in dev)   │
│   calls rl_env.* directly (in-process Python)                    │
└────────────────────────────┬─────────────────────────────────────┘
                             │
            ┌────────────────┴──────────────────┐
            │ in-process worker threads          │
            │ (reconstruction, training)         │
            │                                    │
            │ Inngest worker process planned     │
            │ for v3.1-deploy.                   │
            └───────────────────────────────────┘
```

Everything in one `docker compose up`: `postgres`, `inngest-dev`, `api`,
`worker`, `frontend`.

## Data model

Six tables, all in `backend/src/models/__init__.py`. FK chain:

```
project ──┬── reconstruction ──── validation
          ├── build ──── policy ──── run
          └── (video file on disk)
```

`ON DELETE CASCADE` everywhere so deleting a project removes the lineage.

## Feature modules

`backend/src/features/<x>/` each has:

- `router.py` — FastAPI routes
- `service.py` — business logic, called by routes and Inngest functions
- `inngest_functions.py` — durable workflows (the dev-server invocation
  handshake has rough edges; until that's fixed we also kick the work in
  a background thread from the route — same code path, no behavior change)

| Feature | Endpoints |
|---|---|
| projects | CRUD + `/state` + `/summary` + `/runs` + `/export` |
| reconstruction | `/backends`, `/upload-video`, `/reconstruct`, `/reconstruction` |
| validation | `/validate`, `/validate/latest` |
| builds | `/build` |
| training | `/train`, `/policies`, `/policies/{id}` |
| replay | `/replay` |

## Reconstruction plugin interface

`backend/src/features/reconstruction/backends/` —
ABC + registry pattern. New backends register via `@register`; UI surfaces
them via `GET /api/reconstruction/backends`.

| Backend | Status |
|---|---|
| `demo_fixture` | implemented (no-GPU procedural room — used by tests + offline demos) |
| `vggt` | implemented (real model; raises clear error if no GPU/weights) |
| `splat` | stubbed for change `worldscan-v2.1-splat` |
| `colmap` | stubbed for change `worldscan-v2.2-colmap` |
| `depth_fusion` | stubbed for change `worldscan-v2.3-depth-fusion` |

See `docs/adding-a-reconstruction-backend.md` for the recipe.

## Stage gating

`GET /api/projects/{id}/state` returns per-stage `{complete, reason}`
derived from real artifacts:

| Stage | Complete when |
|---|---|
| capture | video uploaded |
| reconstruct | a `reconstruction` row has `status='ok'` |
| validate | the latest validation overall is `pass` or `warn`, OR `user_override` was set |
| build | a `build` row exists |
| train | a `policy` row exists |
| replay | a `build` row exists |

The frontend's `StepNav` reads `/state` and locks future steps until
their prerequisite stage completes. `Sidebar`'s status pill is derived
from the same artifact ordering in `/summary`.

Theme tokens live in `frontend/src/index.css` — dark-only by default,
oklch colors, Geist Sans + Mono. Linear / Blender / Three.js editor
feel.

## Type sharing

`backend → /openapi.json → shared/openapi.json → shared/ts/api.d.ts`.

`just typegen` runs this pipeline. Husky pre-commit hook keeps the
generated client current.

## Local dev

```bash
just dev           # docker compose up --watch (5 services)
just db-migrate    # alembic upgrade head
just typegen       # backend openapi.json → typed client
just test          # backend pytest + frontend vitest
```

Ports: frontend 5173, api 8000, postgres 5433, inngest-dev 8289. The 5433
+ 8289 choices avoid clashing with the team's sibling Haleum stack on
the same host.

## Where to add things

- **New reconstruction backend** → `docs/adding-a-reconstruction-backend.md`
- **New validation check** → add a function to
  `backend/src/features/validation/checks.py` and register it in `CATALOG`
- **New stage / route** → `backend/src/features/<x>/` (router + service +
  optional inngest_functions); update `/state` derivation
- **New screen** → `frontend/src/routes/p.$projectId.<x>.tsx` + update
  `StepNav.tsx`
